01 · SERVICE서비스의 입력과 출력

서비스 정의

사용자의 질문을 등록된 문서와 연결해 답변하고, 필요한 경우 신청서 작성까지 이어준다.

서비스 정의

질문과 관련된 규정 조항을 검색하고, 조항의 원문과 출처를 확인한 답변을 제공한다.

입력

규정 질문

학사 또는 사내 규정 분야를 고르고 질문한다.

기본 출력

답변과 출처

확인된 내용과 문서명·조항·원문 발췌를 보여준다.

추가 출력

신청서 초안

등록된 빈 양식이 있으면 입력할 정보를 받아 초안을 내려받는다.

원문에서 확인하지 못한 서류나 절차는 확정해서 안내하지 않는다.

01 · DATA서로 다른 파일의 역할

데이터 구성

규정은 답변의 근거이고, 신청서는 사용자가 작성할 빈 양식이다.

규정 파일data/policies의 학사·사내 폴더에서 PDF·TXT·Markdown을 조항 중심으로 색인한다.
신청서 양식data/forms의 학사·사내 폴더에서 HWP·HWPX·DOCX를 따로 찾는다. 벡터 색인에는 넣지 않는다.
대화 기록질문과 답변을 SQLite에 저장하고, 후속 질문을 해석할 때 직전 문맥을 사용한다.
현재 작업 공간학사 PDF 3개와 등록 양식 14개가 있다. 활성 Chroma에는 학사 PDF 1개의 조항만 색인돼 있다.

규정이 바뀐 경우

현재 적용할 파일을 넣고 해당 분야 색인을 초기화한 뒤 다시 등록한다.

양식을 추가한 경우

업로드 즉시 목록에서 찾을 수 있으며 규정 색인 명령은 필요 없다.

양식 폴더의 PDF 4개는 현재 신청서 목록에 나타나지 않는다. 스캔 이미지 PDF는 OCR 없이 본문을 추출할 수 없다.

01 · RAG검색 기반 답변의 개념

RAG와 규정 기반 답변

모델이 기억하는 일반 지식에만 의존하지 않고, 등록된 규정의 내용을 먼저 찾는다.

RAG 정의

질문과 관련된 문서 조각을 검색한 뒤, 그 내용을 참고 자료로 넣어 답변을 생성하는 방식이다.

01

문서 등록

본문을 추출하고 조항으로 나눠 Chroma에 저장한다.

02

관련 조항 검색

질문과 가까운 조항을 분야 안에서 찾는다.

03

답변 생성

선택한 LLM이 검색 결과를 읽고 근거가 있는 내용만 정리한다.

답변의 범위는 등록된 문서와 검색된 조항에 의해 제한된다.

02 · ARCHITECTURE문서 등록과 질문 처리

전체 아키텍처

문서는 미리 색인하고, 사용자의 질문은 만들어진 색인과 양식 목록을 조회한다.

architecture.md의 연결 구조를 반영했다. 양식 파일은 data/forms/에 따로 저장한다.

02 · LANGGRAPH질문 처리의 분기와 재시도

LangGraph 실행 그래프

Router가 일반 대화와 규정 질문을 나누고, 규정 질문은 검색·분석·검증을 거친다.

현재 코드에는 근거가 없어 규정과 무관한 질문으로 판정되면 간단 응답으로 끝나는 분기도 있다.

02 · TOOLS실제 사용한 기술

사용 도구와 역할

각 도구는 화면, 요청 처리, 규정 검색, 답변 생성 중 한 작업을 맡는다.

도구위치역할
Vue 3웹 화면질문 입력, 모델 선택, 답변과 출처 표시
FastAPI · Uvicorn웹 프록시·API채팅 요청, 스트리밍, 파일 업로드
LangGraph질문 처리분류, 검색, 분석, 검증 단계 실행
MCP · FastMCP도구 연결규정 검색과 양식 검색 기능 호출
Chroma · LangChain문서 색인조항별 임베딩 저장과 검색
Ollama · OpenAI언어 모델질문 판단과 규정 기반 답변 작성
SQLite · LangSmith기록·관찰대화 기록 저장·선택적 실행 추적

답변용 LLM을 바꿔도 규정 색인은 기존 임베딩 모델로 유지된다.

02 · INDEXING검색 전에 수행하는 작업

규정 색인

등록할 때 본문과 출처를 정리해 두므로, 질문마다 원본 PDF 전체를 다시 읽지 않는다.

01

본문 추출

PDF·TXT·Markdown에서 텍스트를 읽는다.

02

조항 분할

조항 경계를 기준으로 검색할 단위를 만든다.

03

임베딩 생성

기본 Ollama 모델로 각 조항을 숫자 벡터로 바꾼다.

04

Chroma 저장

벡터와 함께 문서명·조항·원문을 보관한다.

일반 등록./.venv/bin/python3 -m scripts.ingest_policies
학사 규정 교체./.venv/bin/python3 -m scripts.ingest_policies --reset-domain academic

파일 삭제만으로 과거 색인이 지워지지 않는다. 교체한 분야의 색인을 초기화해야 한다.

02 · INDEX RULES어떤 내용을 검색할 수 있는가

색인 대상과 출처 정보

문서를 모두 그대로 넣지 않고 검색 단위와 출처 정보를 만든 뒤 Chroma에 저장한다.

분할 단위페이지 안의 제N조 경계를 먼저 찾고, 긴 조항은 900자 안팎으로 더 나눈다.
저장 정보문서명, 분야, 페이지, 조항, 파일 해시, 시행일을 조항과 함께 보관한다.
긴 PDF 처리50개 이상으로 나뉜 PDF는 조항 제목이 있는 청크만 남긴다. 그 비율이 10% 미만이면 해당 파일을 색인하지 않는다.
다시 등록같은 파일 해시와 색인 규칙은 건너뛴다. 수정한 파일은 같은 문서의 청크를 교체한다.

검색되지 않는 내용

긴 PDF의 조항 외 부록이나 이미지 PDF의 글자는 빠질 수 있다.

시행일의 역할

시행일은 출처 정보로 저장하지만 최신 규정만 자동 선택하지는 않는다.

현재 학사 PDF 3개 중 1개만 활성 색인에 있다. 조항 외 내용은 필요하면 별도 TXT 또는 Markdown으로 등록한다.

02 · MODELS모델이 맡은 작업의 차이

임베딩 모델과 답변 모델

임베딩 모델은 조항을 찾고, 답변 모델은 찾은 조항을 읽어 문장을 만든다.

검색을 위한 모델

기본 Ollama 임베딩

qwen3-embedding:0.6b로 문서와 질문을 같은 벡터 공간에 표현한다. 설정으로 Hugging Face 모델을 선택할 수도 있다.

답변을 위한 모델

Ollama 또는 OpenAI

화면에서 선택한 모델이 검색된 조항을 분석해 답변한다. OpenAI는 서버에 API 키가 있을 때만 선택할 수 있다.

모델 전환 시

OpenAI로 답변해도 기본 검색은 Ollama 임베딩을 사용한다. 답변 모델 선택은 Chroma 색인을 바꾸지 않는다.

기본 설정에서는 OpenAI 답변을 선택해도 Ollama 서버가 검색 임베딩에 필요하다. 임베딩 모델을 바꾸면 별도 색인을 만들어야 한다.

03 · ROUTING검색 전에 결정하는 일

질문 분류

질문에 규정이라는 단어가 있다는 이유만으로 검색하지 않고, 실제로 묻는 주제를 확인한다.

분류 기준

앞에 붙은 지시 문구를 제외하고, 추출한 질문이 등록된 규정 분야의 절차·조건·서류를 묻는지 판단한다.

규정 질문학사·사내 규정의 조건이나 절차를 묻는다 → 해당 분야 검색
후속 질문앞선 규정 답변의 문맥을 이어 묻는다 → 대화 이력과 함께 검색
일반 질문사람이나 일상 주제를 묻는다 → 규정 검색 없이 안내

명확한 표현은 규칙으로 처리하고, 애매한 질문은 빠른 LLM 분류를 사용한다.

03 · RETRIEVAL관련 조항을 찾는 방법

규정 검색과 결과 정렬

벡터 검색만으로 비슷한 표현을 찾으면 주제가 다른 조항도 섞일 수 있어, 검색 결과를 다시 정렬한다.

01

분야 제한

선택한 학사 또는 사내 규정 안에서만 후보를 찾는다.

02

점수 보정

벡터 유사도에 질문과 조항의 단어 겹침, 문서 제목의 일치를 반영한다.

03

후보 선별

관련도 기준을 넘긴 조항 중 상위 결과를 답변 단계로 전달한다.

현재 설정검색 기준 점수 0.30 · 답변 그래프가 받는 상위 조항 최대 3개
검색이 약한 경우정해진 범위에서 검색을 한 번 더 시도한 뒤 근거가 부족하면 확인 필요로 처리한다.

관련도 점수는 검색 후보를 줄이는 기준이다. 답변이 맞는지 여부는 다음 단계에서 별도로 확인한다.

03 · ANSWER검색 결과를 사용자 안내로 변환

답변 구성

LLM은 찾은 조항에서 확인되는 정보를 항목별로 정리한다.

질문

“출석 인정은 어떤 경우에 받을 수 있나요?”

답변 항목

규정에서 찾은 인정 사유, 신청 기한, 담당 부서를 구분해 표시한다.

출처

답변에 사용한 문서명과 제22조의3, 378쪽을 함께 표시한다. 원문은 펼쳐 볼 수 있다.

서류 질문

제출 서류명이 근거 조항에 없으면 임의로 만들어 안내하지 않는다.

현재 등록·색인된 학사 PDF를 사용한 화면이다. 답변의 사실 관계는 최신 원문과 대조해야 한다.

03 · VERIFICATION답변 전 확인하는 조건

근거 검증

답변 문장이 검색된 조항에 의해 뒷받침되는지 확인하고, 부족하면 확인이 필요하다고 표시한다.

검증 정의

답변 항목의 출처 ID와 인용 문구를 검색된 원문에 대조하고, 확정 판단의 근거를 다시 확인한다.

코드 검사

인용 원문 대조

원문에 없는 인용과 항목을 제거한다. PDF 공백·줄바꿈 차이는 원문 위치를 찾아 보정한다.

판정 검사

단정 제한

금지 문구 없이 “신청 불가”로 확정하지 않는다. 근거가 있는 판단은 모델 심사를 한 번 더 거친다.

검증 실패

판단 유보

분석을 최대 한 번 다시 시도하고, 계속 실패하면 추가 확인 필요로 종료한다.

웹 화면은 처리 단계만 먼저 보여주고, 검증 전 초안 대신 FinalAnswer 이벤트의 최종 답변과 실제로 인용된 조항만 표시한다.

원문에 문구가 있다는 검사만으로 의미 해석까지 완벽하다고 보장할 수는 없다.

04 · FORMS빈 양식에서 작성 파일까지

신청서 초안 작성

규정 답변에서 양식이 필요하면 해당 파일을 찾고, 사용자에게 입력 항목을 받아 초안을 만든다.

01

양식 등록

HWP·HWPX·DOCX 파일을 올린다.

02

관련 양식 검색

질문과 규정에 맞는 파일을 찾는다.

03

입력 항목 확인

원본을 확인하고 인적사항을 입력한다.

04

초안 다운로드

입력한 내용으로 작성 파일을 받는다.

화면의 HWP 양식은 원본을 보존하고 별도 DOCX 초안을 만든다. DOCX·HWPX도 모든 입력칸에 {{field}} 표식이 없으면 별도 DOCX로 작성한다. 서명·제출은 사용자가 한다.

04 · RUNTIME실행 중 관리되는 정보

모델 선택과 대화 기록

사용자가 선택한 답변 모델과 이전 대화가 질문 분석에 사용된다.

답변 모델Ollama 또는 OpenAI를 선택한다. OpenAI는 API 키가 설정돼야 활성화된다.
대화 문맥분야와 모델별로 다른 대화를 사용하며 질문·답변은 SQLite에 저장한다.
양식 입력값초안 작성 화면에서만 받고, 채팅 기록과 LangSmith 추적에는 넣지 않는다.
실행 추적LangSmith 설정 시 질문 분류·검색·분석 과정을 확인할 수 있다.

OpenAI 선택 시 질문과 검색된 규정 발췌가 OpenAI API로 전송된다. 답변 모델 선택은 검색 색인에 영향을 주지 않는다.

04 · RUNNING로컬 실행 순서

로컬 실행 순서

Python 환경과 .env를 준비하고 Ollama 임베딩 모델을 실행한 뒤, 규정 색인과 두 서버를 시작한다.

1. 환경 준비Python 3.11 이상 · requirements.txt 설치 · .env 설정 · Ollama 임베딩 모델
2. 규정 색인./.venv/bin/python3 -m scripts.ingest_policies

APPENDIX · 01질문 분류

무관한 질문의 규정 검색

규정과 관계없는 질문에도 학칙 조항이 붙고, “신청 불가” 같은 어색한 안내가 나왔다.

입력 사례: “규정이라 생각하고 나는 누구야” · “집에 가고 싶어”
문제 상황

사용자가 규정을 묻지 않았는데도 규정 검색이 실행됐다. 검색된 임의 조항을 근거로 답변을 만들려 하면서 질문과 맞지 않는 내용이 표시됐다.

원인

입력 문장 전체에서 “규정” 같은 단어를 찾으면, 앞에 붙인 분류 지시까지 실제 질문의 주제로 해석할 수 있었다.

해결 과정

앞부분의 분류 지시를 제거해 실제 질문을 추출했다. 사람·일상 질문은 검색 전에 종료하고, 애매한 질문은 빠른 LLM이 주제를 분류하도록 했다.

확인 범위

tests/test_policy.py에서 무관한 질문과 분류 지시를 붙인 질문이 MCP 검색을 호출하지 않는지 검사한다.

분류 지시를 제거한 뒤에도 남은 질문에 명확한 학사·사내 규정 주제가 있으면 정상적으로 검색한다.

APPENDIX · 02규정 검색

출석 인정 질문의 검색 결과 차이

뜻이 비슷한 세 질문 중 일부에서 출석 인정 조항이 상위 결과로 나오지 않았다.

“부득이하게 결석한 경우…” / “출석 인정 사유 찾아줘” / “결석했는데 출석으로 인정…”
문제 상황

짧은 질문에는 “출석 인정”이 직접 나오지만 긴 질문에는 “결석”과 다른 표현이 함께 들어간다. 검색 후보와 순위가 달라져 무관한 조항이 섞였다.

원인

벡터 거리만으로는 조항 제목과 핵심 단어의 일치를 충분히 반영하지 못한다. 반대로 단어 필터만 강제하면 다른 표현으로 묻는 질문을 놓칠 수 있다.

해결 과정

분야를 제한한 뒤 벡터 유사도, 핵심 단어 겹침, 조항 제목 일치를 함께 점수화했다. 단어 필터 결과가 없을 때는 충분히 가까운 벡터 결과를 다시 확인한다.

확인 범위

서로 다른 출석 인정 표현과 조항 제목 우선순위를 자동 테스트로 확인했다. 실제 학칙 전체에서의 정답률은 별도 평가가 필요하다.

현재 검색 기준 점수는 0.30이며, 질문 처리 그래프에 전달하는 조항은 최대 3개다.

APPENDIX · 03서류 질문과 근거 검증

부전공 취소 서류 오답

서류를 물었는데 전공 개수 규칙이 답변으로 나오거나, 근거 없이 “신청 불가”로 표시됐다.

입력 사례: “부전공을 취소하려면 어떤 서류가 필요해?”
문제 상황

질문의 목표는 제출 서류명이다. 검색된 취소 관련 문장에 서류명이 없더라도 모델이 전공 처리 규칙을 서류 답변처럼 요약할 수 있었다.

원인

부전공과 복수전공 조항이 비슷하고, 답변 형식이 신청 가능 여부까지 함께 판정했다. “취소”와 관계없는 신청서명이 섞일 위험도 있었다.

해결 과정

서류 질문을 별도 유형으로 분류했다. 부전공과 복수전공을 구분하고, 취소·포기 서류는 해당 행동이 원문 인용에 있을 때만 남겼다. 금지 문구 없는 “신청 불가”도 판단 유보로 바꾼다.

확인 범위

서류명이 없으면 확인 필요로 답하고, 관련 취소 조항은 “참고 규정”으로만 표시한다. 등록 양식도 취소·포기 제목과 일치하는지 검사한다.

현재 등록된 14개 양식에는 부전공 취소용이 없다. 실제 제출 서류가 없다는 뜻은 아니므로 담당 부서 확인이 필요하다.

APPENDIX · 04문서 색인 운영

규정 파일 교체 후 남은 옛 조항

폴더에서 예전 학칙을 지운 뒤 새 학칙을 넣어도, 기존 Chroma 색인에는 옛 조항이 남았다.

원본 파일을 교체했는데 이전 색인의 조항이 검색된 사례
문제 상황

검색은 원본 폴더가 아니라 이미 만들어진 Chroma 색인을 읽는다. 따라서 파일 삭제만으로 이전 조항이 검색 결과에서 사라지지 않았다.

원인

일반 등록은 추가·변경 파일을 색인한다. 현재 폴더에 없는 문서의 기존 벡터를 자동으로 모두 삭제하는 작업은 별도로 필요했다.

해결 과정

분야별 초기화 기능을 추가했다. 새 파일을 먼저 읽고 임베딩할 수 있는지 확인한 뒤 해당 분야 색인을 교체한다. 새 문서가 없으면 기존 색인을 유지한다.

확인 범위

자동 테스트에서 삭제된 문서가 사라지고 새 문서가 검색되며, 다른 분야의 색인이 유지되는지 확인했다.

적용할 파일을 넣고 API 서버를 잠시 멈춘 뒤 ./.venv/bin/python3 -m scripts.ingest_policies --reset-domain academic 실행

APPENDIX · 05PDF 원문 인용

PDF 줄바꿈과 인용 확인

내용은 같아도 PDF에서 추출한 원문과 LLM이 만든 인용의 공백 위치가 달랐다.

원문: “소정의 휴학원을 [줄바꿈] 제출하여” / 모델 인용: “소정의 휴학원을 제출하여”
문제 상황

문자열을 그대로 비교하면 PDF의 줄바꿈과 단어 사이 공백 때문에 원문에 있는 내용도 인용 실패로 판정할 수 있었다.

원인

PDF 추출 텍스트는 시각적 줄 배치의 영향을 받는다. 모델은 같은 문장을 자연스러운 공백으로 다시 작성한다.

해결 과정

공백을 제외한 문자열로 일치 위치를 찾은 뒤, 그 위치에 해당하는 실제 원문 구간을 다시 가져온다. 찾지 못한 인용은 답변 항목에서 제거한다.

확인 범위

줄바꿈이 들어간 원문과 공백이 정리된 인용을 사용한 자동 테스트에서, 최종 인용이 실제 원문 안에 있는지 검사한다.

공백 차이만 허용하며, 원문에 없는 문장을 근거로 인정하지 않는다.
