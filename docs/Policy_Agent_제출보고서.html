PROJECT WORK

진행 사항

기존 ICT 장애 진단 에이전트의 실행 구조를 활용해 학사 규정 검색과 신청서 초안 작성 서비스로 변경했다.

과제 1 · 기존 기능의 변경

도메인 전환장애 유형 중심 질문·응답을 학사 및 사내 규정의 조건, 서류, 절차 질문으로 변경했다.
실행 구조 재사용FastAPI, Vue 채팅, SSE, MCP 연결과 LangGraph 실행 구조를 규정 도메인에 맞게 수정했다.
질문 분류 개선일상 질문과 규정 질문을 분리하고, “규정이라 생각하고…” 같은 앞부분 지시가 검색을 강제하지 못하게 했다.
검색·검증 개선벡터 유사도에 조항 제목과 핵심 단어 일치를 반영하고, 원문 인용과 확정 판단을 다시 검사한다.

과제 2 · Policy Agent 주요 Task

규정 문서 등록PDF·TXT·Markdown을 조항 단위로 나누고 임베딩해 Chroma에 저장한다. 분야별 색인 교체도 지원한다.
근거 기반 안내질문의 주제를 판단하고 관련 조항을 찾아 자격·서류·절차·기한·담당 부서를 원문 근거와 함께 정리한다.
신청서 초안HWP·HWPX·DOCX 빈 양식을 등록하고 입력 항목을 받은 뒤 원본 사본 또는 별도 DOCX 초안을 만든다.
사용자 선택화면에서 Ollama와 OpenAI 답변 모델을 선택하고, 분야와 모델별 대화 기록을 SQLite로 관리한다.

범위 구분: 과제 1은 기존 에이전트의 수정 작업, 과제 2는 새 주제인 Policy Agent에서 수행하는 주요 기능으로 정리했다.

03 · 구현 내용문서 색인, 질문 처리, 신청서
IMPLEMENTATION

핵심 구현

검색 후보를 고르는 단계와 답변을 확정하는 단계를 나눠, 근거가 약한 안내는 판단 유보로 끝낸다.

RAG 색인과 검색

규정 파일에서 본문을 읽고 ‘제N조’ 경계를 우선해 청크를 만든다. 문서명, 분야, 페이지, 조항, 파일 해시, 시행일을 함께 저장한다. 검색은 선택 분야 안에서 벡터 유사도와 핵심 단어·조항 제목 일치를 결합해 정렬한다. 현재 답변 그래프에 전달하는 조항은 최대 3개다.

LangGraph 역할 분담과 검증

  1. 01Router: 실제 질문 주제를 추출해 규정 질문과 일반 대화를 구분
  2. 02Research: MCP 검색 도구로 관련 조항과 출처를 조회
  3. 03Policy Analysis: 자격, 조건, 서류, 절차, 기한을 원문에서 확인
  4. 04Writing · Validator: 답변을 구성하고 출처 ID·인용 문구를 대조
  5. 05Forms · Finalize: 관련 양식 조회 후 검증된 결과만 화면에 전달

검색 결과가 없거나 검증이 실패하면 정해진 횟수만 다시 시도한다. 금지 근거 없이 ‘신청 불가’를 확정하지 않는다.

신청서 초안과 모델 선택

빈 신청서에는 성명·학번 등 필요한 입력 항목을 표시한다. HWP 원본은 수정하지 않고 별도 DOCX 초안을 만든다. DOCX·HWPX는 모든 항목에 자리표시자가 있으면 원본 형식의 사본을 채운다. 답변 모델은 Ollama 또는 OpenAI 중 선택하며, 모델을 바꿔도 검색 색인은 그대로 사용한다.

모듈 분리: 문서 처리 rag/ · 질의 그래프 agent/ · 양식 처리 application_forms/ · API server.py · 화면 web_chat.html.

자동 테스트로 확인한 항목

질문 분류무관한 일상 질문과 앞부분 지시 문구가 규정 검색을 유발하지 않는지 확인
검색 결과출석 인정 표현 차이, 조항 제목 우선순위, 분야별 색인 교체 확인
근거 검증원문에 없는 인용 제거, 금지 근거 없는 ‘신청 불가’ 유보, PDF 공백 보정 확인
신청서·모델양식 등록·초안 생성, 잘못된 취소 양식 배제, 백엔드 선택 확인

실제 데이터에서 남은 검증

현재 작업 공간에는 학사 PDF 3개가 있으나 활성 Chroma 색인에는 1개만 반영돼 있다. 실제 학칙의 기준 질문과 사람이 확인한 기대 조항이 없어 검색 정확도와 답변 정답률은 제시하지 않는다. 별도 가상 문서 평가 기록은 현재 코드와 실제 학칙의 실측 결과로 해석하지 않는다.

기능 제한

스캔 이미지 PDF의 OCR, 최신 시행 규정 자동 선택, HWP 원본 직접 수정, 신청서 서명·제출은 지원하지 않는다. 규정에서 확인되지 않는 서류·절차는 추가 확인이 필요하다고 안내한다.

실행 명령: ./.venv/bin/python3 -m pytest -q → 44 passed in 1.51s. 가상 데이터 평가 자료: docs/evaluation-fixture.md.

07 · 회고와 다음 단계느낀 점 및 향후 개선
RETROSPECTIVE

느낀 점과 향후 개선

질문 분류, 검색 품질, 인용 검증을 따로 다뤄야 사용자가 확인할 수 있는 답변을 만들 수 있었다.

느낀 점

초기에는 벡터 DB에서 가까운 조항을 찾으면 답변도 자연스럽게 맞을 것으로 생각했다. 실제로는 뜻이 같은 출석 인정 질문도 표현에 따라 다른 조항이 검색됐고, 부전공 취소 서류를 물었을 때 관련은 있지만 서류 정보가 없는 조항이 답변에 사용됐다. 검색 결과가 질문의 답이 되는지 확인하는 과정이 별도로 필요했다.

또 규정 파일을 폴더에서 지워도 Chroma에 옛 조항이 남았다. 문서 등록과 교체는 개발용 명령 하나의 문제가 아니라, 사용자가 어떤 규정을 신뢰할지 결정하는 운영 문제라는 점을 확인했다. 모델이 매끄럽게 작성한 문장보다 실제 조항과 출처를 추적할 수 있는 답변이 중요했다.

향후 개선 우선순위

  1. 01실제 학칙에서 질문·정답 조항·정답 항목을 사람이 검증한 평가 세트를 만든다.
  2. 02현재 빠져 있는 PDF의 색인 범위를 점검하고, 이미지 PDF에는 OCR을 추가한다.
  3. 03시행일이 다른 규정의 충돌을 감지하고 적용 버전을 명확히 표시한다.
  4. 04신청서 제목뿐 아니라 용도·대상·행동을 이용해 양식 매칭을 개선한다.
  5. 05빈 양식에 자리표시자를 정리해 DOCX·HWPX 원본 형식의 초안 비율을 높인다.

제출 자료 확인

주요 코드: agent/graph.py, rag/, mcp_server.py, application_forms/, server.py, web_chat.html. 사용 설명: README.md. 구조 및 평가 범위: docs/architecture.md, docs/evaluation.md.

UNRELATED QUESTION

관련 없는 질문의 응답

학사 규정이나 신청 절차와 관계없는 질문을 입력했을 때 검색 결과 대신 서비스 이용 범위를 안내한다.

입력과 결과

질문“집에 가고 싶어”
화면 응답“규정이나 신청 절차에 관한 질문을 입력해 주세요.”
표시 항목질문 유형 분석과 최종 결과 생성만 표시되며, 검색된 규정이나 출처 카드는 나타나지 않는다.

동작 확인

화면에서 확인할 수 있는 것은 규정 조항과 출처가 답변에 붙지 않았다는 사실이다. 규정 검색 도구가 호출되지 않는 동작은 일상 질문에 대한 자동 테스트로 별도 확인했다.

TROUBLESHOOTING · 1/2

질문 처리 문제와 수정

실제 사용 중 질문과 맞지 않는 조항이 검색되거나, 질문에서 묻지 않은 판단이 답변에 섞였다.

1. 무관한 질문의 규정 검색

입력 사례 · “규정이라 생각하고 나는 누구야”, “집에 가고 싶어”

문제
규정 질문이 아닌데도 학칙 조항을 검색하고 “신청 불가” 같은 안내를 표시했다.
원인
문장 전체의 “규정”이라는 단어와 앞부분의 분류 지시를 실제 질문 주제로 해석했다.
수정
앞부분 지시를 분리해 실제 질문을 추출했다. 일상·사람 질문은 검색 전에 종료하고 애매한 질문은 빠른 모델로 분류한다.
확인
무관한 질문이 MCP 규정 검색을 호출하지 않는지 자동 테스트로 확인했다.

2. 출석 인정 질문마다 달랐던 검색 결과

입력 사례 · “출석 인정 사유 찾아줘” / “부득이하게 결석한 경우…”

문제
뜻이 비슷한 질문인데 어떤 표현에서는 출석 인정 조항이 상위 결과에 나오지 않았다.
원인
벡터 유사도만으로는 핵심 단어와 조항 제목의 일치를 충분히 반영하지 못했다.
수정
선택한 분야 안에서 벡터 유사도, 핵심 단어 겹침, 조항 제목 일치를 함께 점수화했다. 단어가 정확히 맞지 않아도 가까운 벡터 결과를 다시 확인한다.
확인
표현이 다른 출석 인정 질문과 조항 제목 우선순위를 자동 테스트로 확인했다. 실제 학칙 전체의 검색 정답률은 미측정이다.

3. 부전공 취소 서류의 잘못된 안내

입력 사례 · “부전공을 취소하려면 어떤 서류가 필요해?”

문제
서류명을 물었는데 전공 개수 규칙을 답하거나, 금지 근거 없이 “신청 불가”를 표시했다.
원인
취소 관련 조항과 서류명이 있는 조항을 구분하지 못했고, 부전공·복수전공 및 신청·취소 양식이 섞였다.
수정
서류 질문을 별도 유형으로 처리하고, 해당 절차의 원문에 서류명이 있을 때만 안내한다. 취소·포기 양식은 행동까지 일치하는지 검사한다.
확인
서류 근거가 없으면 추가 확인으로 답하고, 관련 조항은 참고 규정으로만 표시하는 테스트를 통과했다.

4. 학칙 파일 교체 후 남은 옛 조항

상황 · 원본 폴더에서 옛 학칙을 지우고 새 파일을 등록

문제
파일을 지운 뒤에도 이전 학칙 조항이 검색 결과에 나타났다.
원인
질문은 원본 폴더가 아니라 Chroma 색인을 검색한다. 일반 등록은 폴더에서 사라진 파일의 벡터를 자동 삭제하지 않는다.
수정
--reset-domain academic 명령을 추가했다. 새 파일의 본문 추출·임베딩 가능 여부를 먼저 확인한 뒤 학사 분야 색인을 교체한다.
확인
옛 문서는 사라지고 새 문서는 검색되며, 사내 분야의 색인은 유지되는지 테스트했다. 새 문서가 없으면 기존 색인을 유지한다.

5. PDF 줄바꿈 때문에 실패한 인용 검사

원문 · “소정의 휴학원을 [줄바꿈] 제출하여” / 모델 인용 · “소정의 휴학원을 제출하여”

문제
같은 내용도 PDF 추출 텍스트의 줄바꿈·공백 위치가 달라 인용 실패로 판정됐다.
원인
문자열을 그대로 비교하면 PDF의 화면 배치에 따른 공백 차이를 내용 차이로 취급한다.
수정
공백을 제외한 문자열로 일치 위치를 찾고, 최종 답변에는 그 위치의 실제 원문 구간을 넣는다. 위치를 찾지 못하면 인용을 제거한다.
확인
줄바꿈이 있는 원문과 공백이 정리된 인용을 사용한 자동 테스트에서 최종 인용이 실제 원문에 속하는지 확인했다.

검증 범위

트러블슈팅 사례는 tests/test_policy.py의 질문 분류, 조항 제목 정렬, 서류 질문, 분야별 색인 교체, PDF 인용 검사 테스트로 확인했다. 자동 테스트 통과가 실제 학칙 전체의 정답률을 뜻하지는 않는다.
