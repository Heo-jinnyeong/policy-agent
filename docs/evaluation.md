# 평가 설계와 현재 결과

## 비교 방법

Baseline은 동일 Chroma 인덱스에서 Top-3 검색 1회 후 동일 품질 모델로 구조화 응답을 생성합니다. Proposed는 현재 LangGraph의 MCP 검색, 최대 한 번 재검색, 코드와 모델 검증을 사용합니다. `scripts/evaluate_real.py`가 두 방식을 같은 로컬 환경에서 실행하고 CSV와 Markdown 결과를 씁니다. LangGraph를 직접 실행하므로 API가 답변에 인용한 출처뿐 아니라 실제 검색 후보도 평가할 수 있습니다.

실제 문서 평가 항목은 정답 조항 Top-3 포함, 정답 조항 인용, 인용 문구의 원문 일치, 핵심 사실 포함, 평균 응답시간, 그래프에 기록된 모델 토큰 수입니다. 정답은 문서 ID·PDF 쪽수·조항 제목으로 식별합니다. 핵심 사실은 원문에서 확인한 필수 표현의 포함 여부를 검사합니다. `제1조`처럼 여러 규정에 반복되는 번호만으로 정답을 판정하지 않습니다.

## 테스트 케이스

현재 로컬 작업 공간에는 학사 PDF 3개가 있고, 활성 Chroma 색인에는 그중 학칙·규정집 PDF 1개의 조항 1,059개가 들어 있습니다. 이 문서의 출석, 휴학, 복학, 재입학, 부전공, 학점 인정 조항에서 [실제 문서 정답표](evaluation-real-cases.json) 10개를 작성했습니다. 각 질문의 정답 조항과 핵심 표현이 색인 원문에 있는지 실행 전에 확인했습니다. 나머지 두 PDF와 사내 규정은 이번 측정에 포함되지 않습니다.

| 항목 | 단일 검색 RAG | 현재 Agentic RAG |
|---|---:|---:|
| 정답 조항 Top-3 포함 | 10/10 | 9/10 |
| 정답 조항 인용 | 8/10 | 6/10 |
| 인용 문구 원문 일치 | 4/10 | 8/10 |
| 핵심 사실 포함 | 90% | 60% |
| 평균 응답시간 | 27.92초 | 42.02초 |
| 기록된 모델 토큰 | 23,840개 | 49,916개 |

측정일은 2026-10-22이며, 두 방식 모두 Ollama `qwen3:8b`와 `qwen3-embedding:0.6b` 색인을 사용했습니다. 에이전트의 토큰 수에는 빠른 질문 분류 모델 사용량이 포함되지 않아 실제 총 사용량은 표보다 많습니다. [문항별 결과](evaluation-real-results.md)와 [원본 CSV](evaluation-real-results.csv)에 개별 답변을 남겼습니다. 단일 검색은 정답 조항을 10개 모두 상위 3개 안에 찾았지만, 현재 에이전트는 재입학 질문을 규정 질문으로 처리하지 못했습니다. 두 방식 모두 입대휴학 신청 서류 대신 복학 서류를 답한 사례가 있습니다. 이 10개 문항에서 에이전트의 인용 문구 원문 일치는 높았지만 정답 조항 인용과 핵심 사실 포함은 낮았습니다.

재실행 명령은 `LANGCHAIN_TRACING_V2=false ./.venv/bin/python3 -m scripts.evaluate_real`입니다. 결과의 핵심 사실 판정 표현만 수정했을 때는 `--rescore`로 저장된 답변을 재채점할 수 있습니다.

## 가상 문서 기반 개발 측정

개발 당시의 [가상 데이터 측정 결과](evaluation-fixture.md)와 [케이스별 CSV](evaluation-fixture.csv)는 이전 모델·코드로 측정한 별도 기록입니다. 현재 발표 자료의 수치에는 사용하지 않습니다.

## 알려진 한계와 트레이드오프

코드의 인용 검사는 출처 ID와 원문 인용구의 존재를 확인하지만 모든 의미 왜곡을 증명하지는 못합니다. 모델 심사 역시 오판할 수 있습니다. 이번 10개 문항에서는 에이전트의 추가 검증 비용이 검색·답변 정확도의 개선으로 이어지지 않았습니다. 질문별 오류를 고친 뒤 더 넓은 평가 세트에서 다시 측정해야 합니다. 핵심 사실 포함률은 짧은 표현 검사이므로 모든 동의어와 의미적 정답을 판정하지 못합니다. 평가자가 직접 선정한 10개 질문의 결과를 전체 대학요람의 정확도로 일반화할 수 없습니다.
