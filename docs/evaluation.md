# 평가 설계와 현재 결과

## 비교 방법

Baseline은 동일 Chroma 인덱스에서 Top-3 검색 1회 후 동일 품질 모델로 구조화 응답을 생성합니다. Proposed는 `/chat`의 LangGraph 검색, 최대 한 번 재검색, 자격 판단, 코드와 모델 검증을 사용합니다. `scripts/evaluate.py`가 10개 이상 참조 케이스에 두 방식을 차례로 실행하고 CSV와 Markdown 결과를 씁니다.

측정 항목은 Retrieval Hit@3, 신청 가능 여부 정확도, 인용 ID 정확도, 서류·절차 완전성, 추가 질문 적절성, 평균 응답시간, 모델 토큰 수와 단가 기반 추정 비용입니다. 정답 케이스의 필드는 `question`, `domain`, `expected_article`, `expected_status`; 선택 필드는 `expected_documents`, `expected_procedure`, `expected_follow_up`입니다. 원문에서 확인한 기대값만 입력해야 합니다.

## 테스트 케이스

현재 실제 규정 문서가 없으므로 **실제 문서 근거를 가진 10개 정답 케이스와 실측 성능 결과는 없습니다.** `tests/fixtures/cases.json`에 가상 규정에 기반한 10개 시험 질문을 분리해 두었습니다. 질문은 부전공 포기, 졸업 요건, 휴학, 근거 없는 장학금 질문, 개인 차량 출장, 식비, 과거/최신 문서를 포함합니다. 이 파일의 기대값은 실제 학칙이나 사내 규정을 뜻하지 않습니다.

| 항목 | Baseline | Agentic RAG |
|---|---:|---:|
| 실제 문서 기반 Hit@3 | 미측정 | 미측정 |
| 신청 가능 여부 정확도 | 미측정 | 미측정 |
| 인용 정확도 | 미측정 | 미측정 |
| 서류·절차 완전성 | 미측정 | 미측정 |
| 추가 질문 적절성 | 미측정 | 미측정 |
| 평균 응답시간 | 미측정 | 미측정 |
| 토큰·추정 비용 | 미측정 | 미측정 |

## 가상 문서 기반 개발 측정

실제 규정 평가와 구분해 [가상 데이터 측정 결과](evaluation-fixture.md)와 [케이스별 CSV](evaluation-fixture.csv)를 보관합니다. Ollama `qwen3.5:2b`와 같은 Chroma 인덱스를 사용한 10개 질문에서 Hit@3은 양쪽 모두 0.90, 자격 판단 정확도는 Baseline 0.40, Agentic 0.50이었습니다. 인용 원문 정확도는 0.20에서 0.80으로 높아졌지만, 근거 없는 항목을 제거하면서 서류·절차 완전성은 0.40에서 0.20으로 낮아졌습니다. 평균 응답시간은 5.26초에서 9.33초, 토큰은 총 10,249개에서 26,389개로 늘었습니다. 근거 항목 부족 시 추가 검색을 수행하면서 비용과 시간이 늘어났습니다. 이 작은 가상 세트는 모델 편차가 크므로 실제 문서에서 다시 측정해야 합니다. Ollama 추정 비용은 실제 청구액이 아닙니다.

## 알려진 한계와 트레이드오프

코드의 인용 검사는 출처 ID와 원문 인용구의 존재를 확인하지만 모든 의미 왜곡을 증명하지는 못합니다. 모델 심사 역시 오판할 수 있습니다. 검색 점수와 날짜 충돌 처리에는 실제 문서 기반 튜닝이 필요합니다. Agentic RAG는 재검색·검증 호출이 추가되어 일반 RAG보다 응답시간과 토큰 사용량이 늘 수 있습니다. 그 비용이 정확도 향상으로 상쇄되는지는 실측 전에는 판단할 수 없습니다. 서류·절차 정답 필드를 넣지 않은 케이스는 완전성 점수의 해석력이 낮습니다.
